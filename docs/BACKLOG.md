# A 组：值得直接修（可信度 / 数据风险）

### A-01 同步「静默假成功」
- **现状** ✔：`runSync()` 一进门就是 `if (!engine || running) return true`——**正在同步时第二次调用直接返回成功**。三个真实场景：①**重连**（换密码后重连、或连点两次「测试并首次同步」）时前一次同步还在跑，`connect()` 里 `attach()` 后 `await runSync()` 被这个 `running` 挡掉、返回成功，界面照样提示「已连接，并完成第一次同步」；②定时同步与手动「立即同步」撞车；③**退出前 flush** 此时直接放弃推送，什么都不提示。
- **证据**：`src/main/sync/manager.ts:155`、`:266`、`:351-359`
- **用户感受**：以为数据已上云，换台机器发现没有。
- **成本**：S（改返回值语义 + 给 `manager.ts` 补第一个测试文件，它现在零测试）
- **建议**：做。不做的话同步的「信任」一直有这个洞。
- **决定**：`[x] 做`  `[ ] 不做`  `[ ] 只改文档`

### A-02 旧版本打开新库没有闸门
- **现状** ✔：`migrate()` 只把 `user_version` 读出来给「建默认库」用，然后**无条件**写回 `user_version = 4`。代码里没有「库版本 > 我支持的版本 → 拒绝」这个分支，也没有对应弹框。
- **背景**：`PLAN-UPDATE.md` §3.4-4 把它写成**红线**（「旧版本遇到新库要拒绝而不是硬跑」），理由是怕旧代码读到不认识的表结构后静默写坏数据。
- **加剧项** ✔：`release-notes/v0.6.0.md` 第 2 行明确写「可回退旧版（建议先用备份）」——**等于主动把人往这条没闸门的路上引**。

- **成本**：S~M（读版本 → 高于支持就弹框「请升级」，只给「打开数据目录 / 恢复备份 / 退出」）
